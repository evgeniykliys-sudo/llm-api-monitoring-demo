# llm-api-monitoring-demo

Демонстрация мониторинга и анализа инцидентов для LLM-сервиса: симулятор API с метриками Prometheus + дашборд Grafana + периодическая имитация инцидентов (скачки ошибок и задержки), чтобы дашборд показывал не статичные цифры, а реальный сценарий инцидента.

## Запуск
Нужен установленный Docker Desktop.

```bash
docker-compose up -d
```

- Grafana: http://localhost:3000 (дашборд открывается сразу, анонимный доступ включён; логин/пароль `admin`/`admin`, если нужен полный доступ)
- Prometheus: http://localhost:9090
- Симулятор API: http://localhost:8000/v1/complete (POST), http://localhost:8000/metrics

Дашборд обновляется каждые 5 секунд. Через 3-5 минут после запуска сработает первая имитация инцидента (на 20-30 секунд) — на графиках будет виден скачок error rate и латентности.

## Что смотреть на дашборде
- **RPS** — запросов в секунду
- **Error rate, %** — доля ошибок от общего числа запросов
- **Латентность p50/p95/p99** — распределение времени ответа
- **Ошибки по типу** — rate_limit / timeout / server_error по отдельности

## Как анализировать инцидент
1. Увидел скачок error rate или латентности на дашборде — это инцидент
2. Смотрим логи симулятора за это время: `docker-compose logs simulator --since 5m`
3. В логах — структурированный JSON на каждый запрос (`request_id`, `status`, `duration_ms`, `error_type`, `incident_mode`)
4. По `error_type` понятно, что происходило (например много `server_error` — проблема на стороне сервиса, много `rate_limit` — резкий рост нагрузки)

## Остановить
```bash
docker-compose down
```
