# Архитектура: llm-api-monitoring-demo

## Цель (1 предложение)
Демонстрация мониторинга и анализа инцидентов для LLM-сервиса: симулятор API с метриками Prometheus, дашборд Grafana и периодическая имитация инцидентов (скачки ошибок/задержек), чтобы показать не просто "метрики есть", а реальный сценарий "увидел аномалию на графике → пошёл смотреть логи → понял причину".

## Модули
| Модуль | Файл | Описание |
|--------|------|----------|
| Симулятор LLM API | simulator.py | aiohttp-сервис с эндпоинтом `/v1/complete`, генератор фонового трафика, периодические имитации инцидентов, структурированные JSON-логи, эндпоинт `/metrics` для Prometheus |
| Сбор метрик | prometheus/prometheus.yml | Конфиг Prometheus — scrape симулятора раз в 5 секунд |
| Визуализация | grafana/dashboards/llm-api-dashboard.json | Дашборд: RPS, error rate %, латентность p50/p95/p99, разбивка ошибок по типу |
| Оркестрация | docker-compose.yml | simulator + prometheus + grafana, готово к `docker-compose up` |

## Метрики
- `llm_requests_total{status}` — счётчик запросов (success/error)
- `llm_request_duration_seconds` — гистограмма длительности запроса
- `llm_errors_total{error_type}` — счётчик ошибок по типу (rate_limit, timeout, server_error)

## Схема
```
simulator.py:
  - фоновая задача шлёт себе запросы на /v1/complete с реалистичным распределением задержки
  - раз в ~3-5 минут на 20-30 секунд включается "режим инцидента" — резко растёт доля ошибок
    и задержка (имитация реальной деградации сервиса)
  - каждый запрос: метрики обновляются + структурированный JSON-лог в stdout
    (request_id, status, duration_ms, error_type)

Prometheus (scrape /metrics каждые 5с) → Grafana (дашборд с автообновлением)
```

## Сценарий использования (что должен уметь делать AI-инженер поддержки)
1. На дашборде виден скачок error rate и латентности — это инцидент
2. По времени скачка находим соответствующие строки в логах симулятора (`docker logs simulator`)
3. В логах видно `error_type` — например `rate_limit` или `server_error` — это определяет дальнейшие действия
4. После окончания "инцидента" метрики возвращаются к норме — это видно на графике

## Ограничения демо-версии
- API полностью симулированный — нет реального обращения к LLM
- Инциденты генерируются по таймеру для наглядности, а не по внешним условиям
- Один дашборд без алертинга (в проде — Alertmanager/уведомления при выходе за пороги)
